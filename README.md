# UPC Campus Network AutoLogin

基于 Python 3 的中国石油大学（华东）校园网自动认证与网络状态监控工具。

支持 **Windows / Linux / OpenWrt**，提供网络连通性检测、校园网 Portal 自动发现、掉线自动重连、彩色终端日志以及原始报文 DNS 探测等功能。

本项目参考了 [AutoLogin_Mail for UPC Network Authentication](https://github.com/mrwtong/UPC_WebAutoLogin_Mail)，感谢原作者的工作！

## ✨ 功能特性

- **自动认证**：识别 UPC 校园网认证页面，自动提交账号密码。
- **掉线自动重连**：持续监控网络状态，认证失效后自动尝试恢复。
- **多重连通性检测**：结合 HTTP、HTTPS 和 Portal 重定向判断网络状态。
- **原始报文优化**：Linux 使用 AF_PACKET，Windows 支持 Npcap，直接构造 ARP、IPv4、UDP 和 DNS 报文。
- **DNS 故障降级**：原始报文 DNS → 指定 DNS UDP 查询 → 系统 DNS。
- **彩色终端日志**：保留 `[+]`、`[-]`、`[*]`、`[!]` 状态标识。
- **认证结果复核**：网关返回成功后，再次验证外网连通性，避免误报认证成功。
- **自动重试与退避**：网络异常时控制认证频率，减少重复登录。
- **交互式配置**：运行过程中输入 `x` 并回车，即可修改账号和运营商。
- **跨平台运行**：基于 Python 标准库，无额外 Python 第三方依赖。

> 原始报文主要用于 ARP 和 DNS。HTTP/HTTPS 认证仍使用操作系统的 TCP 协议栈。本工具不会绕过校园网认证系统。

## 📦 运行环境

| 平台 | 系统要求 | 原始报文支持 |
|---|---|---|
| Windows 10 / 11 | Python 3.9+、PowerShell | Npcap |
| Linux | Python 3.9+ | AF_PACKET |
| OpenWrt | Python 3.9+、相应网络接口支持 | AF_PACKET（视固件而定） |

Windows 推荐安装 [Npcap](https://npcap.com/)，以启用原始以太网报文收发。

Linux 原始报文功能需要 root 权限或相应的 `CAP_NET_RAW` 能力。

如果原始报文功能不可用，程序会尝试降级到普通 UDP DNS 查询和系统 DNS 解析。

## 🚀 快速开始

### 1. 获取代码

将 `upc_portal_raw_robust.py` 保存到本地目录。

也可以克隆存放本脚本的项目仓库。

### 2. Windows 运行

建议先安装 Npcap，然后使用管理员 PowerShell 执行：

```powershell
py -3 upc_portal_raw_robust.py
```

指定网卡：

```powershell
py -3 upc_portal_raw_robust.py --iface "Wi-Fi"
```

输出详细诊断日志：

```powershell
py -3 upc_portal_raw_robust.py --iface "Wi-Fi" --debug
```

### 3. Linux 运行

```bash
sudo python3 upc_portal_raw_robust.py
```

指定网卡：

```bash
sudo python3 upc_portal_raw_robust.py --iface wlan0
```

### 4. OpenWrt 运行

在已安装 Python 3 的 OpenWrt 上执行：

```sh
python3 upc_portal_raw_robust.py
```

如需启用原始报文模式，需具备对应权限及内核支持。

部分精简固件可能缺少 Python 标准库组件，需根据实际固件环境补充。

```text

```

当前版本的运营商参数对应关系：

| 选项 | Service 参数 |
|---|---|
| 校园网 | 空字符串 |
| 电信 | `telecom` |
| 联通 | `unicom` |

请注意：原项目中可能使用 `ctcc`、`default`、`local` 等运营商标识，当前版本的参数以实际脚本实现为准。如果校园网认证接口使用不同参数，需要修改对应映射。

### 配置文件

默认配置文件为：

```text
~/.upc.json
```

- Windows：使用 DPAPI 保护保存的密码。
- Linux / OpenWrt：使用权限为 `0600` 的 JSON 配置文件保存密码，**并非加密存储**。
- 兼容读取旧版 `~/.upc` 账号配置，并尝试迁移。

配置文件包含敏感凭据，请勿上传至 GitHub 或公开分享。

当前版本不使用原项目的 `accountList` 多账号配置机制。

### 修改账号

程序运行过程中输入：

```text
x
```

然后按回车，即可重新设置账号、密码和运营商，无需手动编辑配置文件。

## 🌐 网络检测机制

程序通过多个网络检测目标判断当前连接状态。

默认检测地址包括：

```text
http://www.msftconnecttest.com/connecttest.txt
http://captive.apple.com/hotspot-detect.html
https://www.baidu.com/
```

此外，程序可能通过：

```text
http://1.1.1.1/
```

辅助发现校园网 Portal 重定向。

程序采用以下状态：

| 状态 | 含义 | 处理方式 |
|---|---|---|
| ONLINE | 外网连通性检查通过 | 保持监控 |
| CAPTIVE | 检测到可信认证页面 | 尝试自动认证 |
| UNKNOWN | 网络不可访问或探测结果不确定 | 继续检测 |
| LINK_DOWN | 网卡或默认路由不可用 | 等待链路恢复 |

**注意：`UNKNOWN` 不会直接触发登录。** 只有识别出可信的校园网认证页面后，才会提交认证凭据，以减少网络波动造成的重复登录。

### 检测周期

默认检测间隔：

- 网络正常：约 12 秒。
- 网络异常：约 4 秒。

实际检测间隔还会受到请求超时和系统调度影响。

认证失败采用指数退避机制，避免高频率重复请求认证服务器。

## ⚡ 原始报文与 DNS 优化

UPC 校园网常用 DNS 地址：

```text
121.251.251.250
121.251.251.251
```

校园网未认证时，普通系统 DNS 可能无法正确解析认证页面。

因此，本项目会优先尝试使用指定 DNS 服务器进行解析。

### Linux

通过 `AF_PACKET` 尝试：

1. 查询网关 MAC 地址。
2. 直接构造 ARP 请求。
3. 构造以太网、IPv4、UDP 和 DNS 查询报文。
4. 直接发送并接收 DNS 响应。

### Windows

通过 Npcap 的 `wpcap.dll` 尝试：

1. 读取路由表并选择网卡。
2. 获取网卡 IPv4、网关、MAC 和设备 GUID。
3. 使用 Npcap 收发原始以太网报文。
4. 直接构造和解析 DNS 数据包。

不需要安装 Scapy。

### 自动降级

如果底层直接发包失败，程序会依次尝试：

```text
原始以太网 DNS
      ↓
指定 DNS 服务器的 UDP 查询
      ↓
系统 DNS 解析
```

这种机制能够兼顾直接报文探测和不同设备上的兼容性。

需要注意，多网卡、复杂策略路由、VPN、虚拟网络和某些驱动环境可能需要额外适配。

## 🖥️ 运行日志

程序保留彩色状态输出：

| 标识 | 颜色 | 含义 |
|---|---|---|
| `[+]` | 绿色 | 成功、在线、恢复连接 |
| `[-]` | 红色 | 掉线、错误、认证失败 |
| `[*]` | 青色 | 正在探测、认证、执行操作 |
| `[!]` | 黄色 | 警告、重试、状态不确定 |

示例：

```text
[10:30:21] [+] 认证守护进程启动
[10:30:22] [-] 检测到掉线：网络被校园认证页面拦截，将自动重新登录
[10:30:23] [*] 检测到校园认证页面，准备自动登录
[10:30:24] [*] 网关已返回认证成功，正在复核外网连通性...
[10:30:27] [+] 认证成功！账号: example | 网卡: Wi-Fi / IPv4: 10.1.2.3
[10:30:40] [+] 外网在线 | 账号: example
```

以上仅为示例，不代表实际认证结果。

**只有外网检查通过后，程序才会确认网络已经恢复。**

## 🛠️ 常见问题

### Q1：为什么检测不到校园网认证页面？

可能原因：

- 网卡未连接或默认路由异常。
- 指定 DNS 不可用。
- 校园网认证页面地址已经发生变化。
- 认证网关没有返回可识别的 HTTP 重定向。
- Portal 系统使用了不同的参数或认证流程。

可以使用 `--debug` 查看检测情况。

### Q2：为什么网关返回成功，但仍无法上网？

认证接口返回成功不一定代表外网已经恢复。

程序会继续进行连通性验证。如果验证未通过，将继续监控，并根据状态决定是否重新认证。

### Q3：为什么 Windows 没有启用原始报文？

请检查：

- 是否安装 Npcap。
- 是否拥有所需的抓包权限。
- 是否指定了正确网卡。
- Npcap 驱动是否正常运行。

可以通过 `--debug` 查看 DNS 使用方式。

### Q4：断网以后会自动重新登录吗？

会，但需要满足以下条件：

- 网络接口或默认路由已经恢复。
- 程序识别到可信的 UPC 校园网认证页面。
- 当前凭据有效。
- 未处于认证重试等待期。

如果只是普通连接超时或网络状态未知，程序不会盲目提交账号密码。

### Q5：为什么没有使用完全用户态 TCP？

原始 ARP、DNS 查询适合直接构造和发送。

认证 HTTP/HTTPS 涉及 TCP 状态管理、重传、拥塞控制以及 TLS 证书验证。为了降低实现复杂度和连接故障风险，当前版本保留操作系统的 TCP 协议栈。

## 🔒 安全说明

1. 本工具仅通过校园网官方认证流程登录，不用于绕过认证或访问控制。
2. 认证凭据仅应发送至自己确认可信的 Portal 服务器。
3. 部分校园网 Portal 使用 HTTP 接口，这意味着认证凭据可能在传输过程中缺少加密保护，请注意网络安全风险。
4. 不要将本地配置文件提交到公共代码仓库。
5. 使用 `--portal-url` 时，只填写自己已确认可信的认证服务器地址。
6. 本项目为非官方工具，认证服务、参数以及网络策略均可能发生变化。

建议在 `.gitignore` 中添加：

```gitignore
.upc
.upc.json
*.log
__pycache__/
```
